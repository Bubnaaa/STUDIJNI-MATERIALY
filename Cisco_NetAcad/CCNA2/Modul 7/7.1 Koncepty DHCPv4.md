- Dynamicky přiděluje IPv4 adresy a další informace (maska, brána, DNS)

### Server a Klient
- Role serveru 
	- Může jím být server, nebo i Cisco router
	- Spravuje pool adres
- Lease
	- Adresa není přidělena navždy, ale je pronajata na určitou dobu (24h-168h)
- Princip
	- Když vyprší nájem, adresa se vrátí do poolu, pokud klient v síti zůstává, periodicky si nájem obnovuje

### Proces získání adresy (DORA)
1. Discover (DHCPDISCOVER) - klient vysílá broadcast, v packetu používá zdrojovou IP 0.0.0.0

2. Offer (DHCPOFFER) - Server odpoví a nabídne klientovi konkrétní IP adresu, masku a další údaje (unicast/broadcast)

3. Request (DHCPREQUEST) - klient serveru odpoví (broadcastem), že jeho nabídku přijímá. Ostatním serverům v síti tím říká, že jinou nabídku nepotřebuje.

4. Acknowledgement (DHCPACK) - server potvrdí pronájem a klient může adresu začít používat (unicast/broadcast)

### Proces obnovování pronájmu
Klient si obnovuje pronájem ještě před jejím skončení

1. DHCPREQUEST - klient pošle požadavek přímo na server (unicast), který mu adresu pronajal

2. DHCPACK - server potvrdí, že adresu prodlužuje 

- Pokud původní server neodpovídá, klient po určité době začne vysílat broadcast DHCPREQUEST, aby mu nájem prodloužil jakýkoliv jiný DHCP server

### Technické detaily
- Adresování- protože klient na začátku nemá IP adresu, komunikace v prvním kroku probíhá na 2. vrstvě pomocí MAC adres a na 3. vrstvě pomocí 255.255.255.255

- Cisco IOS obsahuje plnohodnotný DHCPv4 server, šetří náklady na HW
